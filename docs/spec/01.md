## 使用规则

本文把本轮需求转换为开发验收契约。**MUST** 为 MVP 必须交付；**SHOULD** 为可以通过明确理由调整的实现建议；**LATER** 不计入 MVP 完成条件。实现策略可以变更，MUST 对应的结果不能因实现困难而静默删除。

最新决定优先于旧聊天和旧 Markdown：短 hint 是可选方向提示；1700 秒是本地默认执行超时；固定模型组合、强制 MCP、默认 SQLite、强制逐条人工批准均不是本项目要求。

## 需求清单

| 编号 | 主题 | MVP 必须实现的结果 |
| --- | --- | --- |
| REQ-01 | 新项目与 KISS | 新名称、新仓库、Rust 核心；只迁移需要的能力；只保留一种正式存储后端。 |
| REQ-02 | 按需求助 | consult 可带一句短 hint，也可省略；不要求调用方输出上下文包；不自动逐轮注入记忆。 |
| REQ-03 | 调用现场 | 准确绑定会话、子 Agent、分支和事件截止点；同 cwd 多 Agent 不串线；历史覆盖范围可检查。 |
| REQ-04 | 四工具兼容 | Claude Code、Codex、Hermes、pi 各自同时提供 CallerAdapter 与 AgentRunner；任一单独安装可使用，组合可配置。 |
| REQ-05 | 原始历史 | 持续采集可访问的用户消息、可见回复、工具记录；保存多轮压缩和分支的原始依据；增量、去重、可恢复。 |
| REQ-06 | 渐进调研 | 外部 Agent/workflow 自主读取历史与代码，按需搜索，可委派子孙任务；整棵任务树共享预算。 |
| REQ-07 | 来源与权威 | 原文、用户确认、用户 taste、代理建议、Auto-Grill 产物、推断均有来源；不能伪造人的认可。 |
| REQ-08 | 可配置模型处理 | 提取、embedding、reranker、调研模型可分别配置；无向量服务时基础检索仍可用；没有额外付费 API 的强依赖。 |
| REQ-09 | Auto-Grill | 支持一个或多个可配置 runner 进行需求探索与复核；保留分歧、证据和停止条件，不要求固定两家模型。 |
| REQ-10 | Review 与校准 | 支持全人工、按策略、自动运行；人工纠正与 taste 能更新后续行为；不要求每条记忆人工审阅。 |
| REQ-11 | 持久历史 | 记忆修订、提交、历史状态、差异、实际返回 receipt 跨重启保留；可高效查看过去状态。 |
| REQ-12 | 外部编辑 | 外部 Agent 使用受控 patch 接口修正记忆；expected\_revision 防止覆盖并发修改；回滚产生新版本。 |
| REQ-13 | 运行反馈 | 测试、运行事件与人工纠正可以创建调查；关联 receipt 和执行产物；暴露不直接等于因果。 |
| REQ-14 | 通知扩展 | 统一 Notifier，持久 outbox、去重、重试；可用的本地通知输出与 stdio 插件接入。 |
| REQ-15 | 配置热重载 | 校验、原子应用、版本号、失败保留旧配置；定义进行中任务语义及少数需重启项。 |
| REQ-16 | 本地长超时 | 本地 provider 请求及本地 runner 默认 timeout 1700 秒；外层不得无意截短；排队、执行、取消语义明确。 |
| REQ-17 | CLI 与本地通信 | CLI + daemon + 私有 IPC；MVP 核心不依赖 MCP 或 TCP 服务；调研轨迹不回灌主 Agent。 |
| REQ-18 | 磁盘存储 | 不采用 SQLite 作为正式运行后端；先验证现代磁盘检索引擎；完整版本和数据不以缓存为唯一副本。 |
| REQ-19 | 资源与并发 | daemon 存储组默认 512MiB 目标、最高 2GiB 配置档；100 客户端、50GB 可检索数据验收；不足时磁盘/排队/背压。 |
| REQ-20 | 检索一致性 | 修订和派生任务原子登记；索引有进度；撤回版本不再错误返回；新修订可等待或查增量。 |
| REQ-21 | 恢复与备份 | 持久确认、崩溃恢复、备份还原、磁盘满受控失败；不得静默丢失已确认写入。 |
| REQ-22 | 迁移与退出 | mempal 数据只读导入、幂等、来源与导入报告；中立格式导出，不强制继承旧实现。 |
| REQ-23 | 证据与评测 | 需求—Issue—测试—提交可追踪；必要运行数据不塞回主上下文；使用真实任务评测。 |
| REQ-24 | 可安装 MVP | 安装、首次配置、四宿主连接、日常操作和恢复文档完整；最终验收以可运行产品及证据为准。 |

## 核心用户路径

1. 用户只安装四种 CLI 中的一种，完成一次连接设置，即可持续保存可获得的历史并求助。
2. Agent 需要记忆时发送一个短 hint 或不发送 hint；系统自动读取调用现场，调研后返回相关结果。
3. 用户明确作出决定，或审阅/修改 Agent 建议后，来源和批准关系被记录；派生摘要可以重建。
4. 用户无暇 review 时，依据既定策略继续 Auto-Grill、提取和调查；代理批准仍标记为代理批准，不冒充人类批准。
5. 用户纠正了错误，系统在当前任务继续推进的同时调度记忆调查；有充分依据且策略允许时自动修订。
6. 软件测试或真实使用暴露问题，系统关联可能相关的记忆，排出 review 优先级并通过可配置通道通知。
7. 用户修改配置，热更新项无需重启；无效配置不会造成半更新；本地慢模型不会被隐藏的短 timeout 截断。
8. 用户查看某个历史提交、某次实际返回或修订差异，并能安全回滚、导出或恢复。

## MVP 的实施范围

- **平台**：Linux 为必须通过端到端验收的平台。macOS、Windows、Termux 的原生安装包装可后置；核心 domain 和协议避免不必要的平台绑定。
- **部署**：单机、单用户记忆服务；同一用户可有很多会话和 Agent。系统通过操作系统访问控制隔离其他本机用户。
- **实现**：Rust 核心。宿主插件需要的 TypeScript/Python 薄适配层允许存在，业务规则只能放一处。
- **检索**：当前有效记忆的关键词搜索、配置后的向量检索和重排，以及外部 Agent 调研。未配置向量服务时必须有可用基础路径。
- **历史**：持久 as-of 状态读取、差异、来源追溯和 receipt 回放必须有；完整历史 ANN 的即时查询可后置。
- **通知**：本地 review inbox/终端可查看，且有可执行的 stdio Notifier 插件契约与示例。不要求第一版内置每一家邮件或聊天 SDK。
- **模型**：支持现有 CLI 会话凭证的正常调用方式，以及配置的本地文本/embedding/reranker endpoint；不硬编码昂贵模型，不要求额外购买 API。
- **资源**：50GB 实际可检索语料及其索引、100 个客户端、冷缓存和恢复场景为必须验证；256MiB/100GB 为扩展实验，不作为已实现能力宣传。

## 明确后置

网页管理 UI、移动端 UI、分布式多节点写入、多租户 SaaS、云账号体系、通用 workflow 编辑器、市场型插件平台、强制 MCP 接入、全版本历史 ANN 常驻、无上限递归调研、自动抓取未授权的数据源。

后置这些项目不能成为后置四种 CLI 接入、基本 Auto-Grill、纠正、review 或热重载的理由。

## KISS 检查

- 一种正式存储实现；备选只在早期实验后决定，不维护两套完整产品后端。
- 优先一个 workspace、少量清楚的模块；不为了每个名词建立 crate、微服务或 RPC。
- 同一语义只实现一次。CLI、插件、daemon 共用 domain 类型和校验。
- 不把所有历史嵌入一个常驻内存结构；摘要和向量是可重建派生物。
- 不复制 mempal 的全部功能。每个迁移能力必须映射到一个 REQ 和验收场景。
- 不把模型输出的置信度直接当作权限、用户批准或客观真相。

## 变更规则

新增或删改必需范围时，先修改相应 REQ、验收矩阵和受影响 Issue，再实现。开发中可以修正技术选型与默认参数，但不能未经记录把“尚未实现”改称“非目标”。
