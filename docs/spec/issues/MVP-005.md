## Issue 正文

\*\*覆盖需求：\*\*REQ-07、REQ-10。

\*\*目标：\*\*系统能区分真人陈述、人工确认、agent 推断、自动讨论和技术事实，不混淆生效与批准。

\*\*范围：\*\*实现 provenance、actor、scope、assumptions、evidence refs、decision kind、authorization、review 标记；支持 taste/原则、项目选择、技术事实和候选结论。人工确认绑定具体 revision/hash；仅有 user role、interactive 标记或环境变量不能伪造 human\_confirmed。已信任宿主输入通道中的明确用户决定，可以依据一次性配置的采纳策略生成有来源的 decision event，不要求用户为同一句决定再点击一次批准；合成 worker 消息不能走这条路径。

\*\*非目标：\*\*不以单一 confidence 分数替代来源和适用范围，不把所有用户发言自动升级为永久原则；不声称同 UID 任意 shell 访问构成可信人机隔离。

\*\*依赖：\*\*MVP-004。

\*\*验收测试：\*\*伪造 author/human\_confirmed 字段被拒绝或降为未验证来源；局部例外不自动覆盖全局规则；修改已审核文本产生新 revision 且不继承旧审核；自动结论可以在授权策略下 active，同时仍明确是 agent 来源。

\*\*完成证据/产物：\*\*数据 schema、权限/优先级规则、包含容易误判例子的 fixtures 与通过记录。
