## Issue 正文

\*\*覆盖需求：\*\*REQ-02、REQ-04、REQ-06、REQ-07、REQ-11、REQ-16、REQ-20、REQ-23。

\*\*目标：\*\*证明精简主上下文没有以遗漏关键决定为代价，且四种宿主的独立/混合使用符合共同契约。

\*\*范围：\*\*使用MVP-011已冻结且早于调研prompt实现的带来源参考集与规则开展评测，覆盖taste、条件、范围、旧版本、分支、无结果、错因与纠正；新增回归集单独标识，不替换或删除原验收集合；比较直接检索和外部 consult；记录主上下文新增 token、追加读取、外部 token/额度、延迟、检索质量和误修订。用组合契约覆盖完整 Caller×Runner 组合空间，并真实执行四个单宿主和代表性交叉组合。

\*\*非目标：\*\*不以 tool-call 次数代替 token/质量，不因主上下文减少就忽略外部成本；不要求 16 种组合每个都做重复昂贵全套实测，但不能只做 mock 便宣称任意组合可用。

\*\*依赖：\*\*MVP-016、MVP-018、MVP-019、MVP-020、MVP-022、MVP-024、MVP-026。

\*\*验收测试：\*\*四个独立场景都在其它三 CLI 缺席时通过；至少四次真实交叉实例形成覆盖四种 Caller 与四种 Runner 的环，例如 Claude→Codex→Hermes→pi→Claude；另对全部 16 种组合做统一契约测试，不要求 16 次重复的昂贵完整场景；每种能力由真实版本与契约证据共同支持；核心不变量无伪造人审、无 scope 泄漏、无撤回复活。按总验收页预先冻结的质量标准逐项判定；关键 scope/撤回/权威不变量零违规，固定关键决定样例全部通过，其余相关性指标达到预注册门槛；评测报告披露失败样本，不以只选成功案例或回放替代真实 CLI 结果。

\*\*完成证据/产物：\*\*评测集/答案来源、可重复运行命令、成本与主上下文对比、组合矩阵、真实回归记录和已修复问题链接。
