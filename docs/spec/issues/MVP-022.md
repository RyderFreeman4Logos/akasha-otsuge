## Issue 正文

\*\*覆盖需求：\*\*REQ-10、REQ-12、REQ-13、REQ-15、REQ-23。

\*\*目标：\*\*无需等用户主动纠正，系统可从有价值的失败信号定位疑似错误记忆并推动处理。

\*\*范围：\*\*可配置触发、去重、优先级、调查预算；调查相关 receipt/run/code，并比较记忆错、漏检、误用、代码错、环境错、需求变化等解释；有证据且获授权时调用 editor，否则进入对应 review；支持依赖变化、到期和直接矛盾等轻量维护触发。

\*\*非目标：\*\*不对每次编译失败打扰用户，不做无限全库反思，不为提升“修复次数”强行改记忆；高优 review 不等于必须冻结全部工作。

\*\*依赖：\*\*MVP-020、MVP-021。

\*\*验收测试：\*\*旧 API 记忆造成失败时只修正相关 scope/版本；环境断网、代码 bug、缺失召回分别走正确路径；无充分归因时保留疑点而不伪造确定性；重试/重复事件不造成重复修订；自动和需 review 策略均可用。

\*\*完成证据/产物：\*\*触发/归因策略、故障分类 fixtures、真实失败到处理的完整链、review 优先级证据。
