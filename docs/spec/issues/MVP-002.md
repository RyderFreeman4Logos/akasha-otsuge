## Issue 正文

\*\*覆盖需求：\*\*REQ-15、REQ-16、REQ-23。

\*\*目标：\*\*配置变化尽量不重启服务，且不会悄悄改变运行中任务的语义。

\*\*范围：\*\*统一配置 schema、优先级、校验与 config\_generation；定义模型 endpoint/模型名、检索预算、并发、review 策略和通知配置的热更新分类，并以可控消费者验证分发；各实际模块在其所属 Issue 中接入；每个 run 记录配置快照。明确只能重启修改的少量设置，例如持久目录或 backend；先实现独立配置管理库、reload/status/doctor 契约和可测试订阅者；生产 daemon 命令接入由 MVP-008 完成。本地三类模型 timeout 默认均为 1700 秒，并定义外层 deadline 的计算和校验规则。

\*\*非目标：\*\*不热切换正式存储 backend，不因配置文件暂时写到一半而停掉当前服务；不把“重新读取文件”冒充所有设置已生效。

\*\*依赖：\*\*MVP-001。

\*\*验收测试：\*\*有效配置进入新任务，运行中任务保留其快照；错误配置保留最后有效版本并报告原因；禁用渠道后配置层的投递许可检查立即拒绝，实际 outbox 投递行为由 MVP-023 验证；虚拟时间测试覆盖 1700 秒与外层更短 deadline 的拒绝逻辑。本项不依赖尚未实现的模型或通知插件才能关闭。

\*\*完成证据/产物：\*\*配置参考、热更新/需重启设置表、配置修订日志、测试结果；实际模型全链长测由 MVP-009 验证。
