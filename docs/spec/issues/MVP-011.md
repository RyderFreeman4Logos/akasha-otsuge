## Issue 正文

\*\*覆盖需求：\*\*REQ-03、REQ-04、REQ-06、REQ-17、REQ-23。

\*\*目标：\*\*使四宿主的上下文来源与执行器可以解耦组合，主 LLM 不需要编写任务包。

\*\*范围：\*\*实现统一 JSONL envelope、request ID/sequence、capabilities 握手、结构化错误/取消/输出限制；runtime 带外 binding 解析 session、turn、branch、cutoff、scope 和 context snapshot。AgentRunner 统一输入、事件、结果、工具权限和预算；delegate 原子预留资源或明确失败回退，禁止父任务占满槽位后无限等待子任务；ContextSource只提供获准读取的来源。按总验收页冻结至少60个有来源的参考任务、oracle、计数规则、参考profile选择方法和门槛，记录commit/hash；冻结必须早于MVP-016的调研prompt实现。

\*\*非目标：\*\*不根据“最近修改的会话文件”猜调用者，不把提示词中的禁止事项冒充实际权限限制，不建设泛化远程 agent 平台。

\*\*依赖：\*\*MVP-007、MVP-008、MVP-010。

\*\*验收测试：\*\*并发 binding 不串线；缺失 binding 返回明确错误；session-only 与精确 turn 能力不混报；未知 capability 有清楚降级/拒绝；协议兼容测试及权限越界测试通过。真实 CLI 验收必须由后四项分别完成。

\*\*完成证据/产物：\*\*协议/trait文档、契约测试套件、binding诊断输出、Runner权限执行策略、冻结评测集及规则的commit/hash。
